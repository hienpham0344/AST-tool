# Recursive DFS recognition and visualization

Status: execution authorized by user request to implement DFS and prior continuous-execution/no-question preference. Scope choices below are builder decisions.

## Behavior
Recognize structural recursive depth-first traversal independently of identifier spelling. First release supports integer vertices, boolean[] visited, int[][] adjacency matrix or java.util.List<java.util.List<Integer>> adjacency lists. A source method marks visited[current]=true before direct neighbor traversal. Matrix scan visits neighbor0..graph.length-1 and guards graph[current][neighbor]!=0 AND !visited[neighbor]; list foreach reads graph.get(current) and guards !visited[neighbor]. Guard body directly calls the same source method with unchanged graph/visited and neighbor as current. Optional entry visited guard/return may be supported only if structurally proven safe. Reject ambiguous overloads/receivers, changed arguments, wrong mark/index/guard/control path, mutation/alias/escape undermining traversal, extra visited writes, early loop break/continue, deferred/lambda recursion. Graph representation/type identity must be proven, not guessed from method or variable names. Conservative omissions are preferable to false labels. Iterative stack DFS, trees without visited, grid DFS, cycle coloring and timestamps are outside this release.

## Architecture and wire
Add nullable AlgorithmHint.dfs metadata schemaVersion1:representation, declarationIds graph/visited/current/neighbor, operationAstNodeIds mark/neighborLoop/guard/recursiveCall and evidence, source method identity. Detection runs at method scope exactly once, not once per nested loop; normal existing detections/constructors stay compatible. Add nullable VisualState.dfsFrame for legacy line mode:actual bounded graph projection, visited vertices/status, current vertex, candidate edge/status, invocation ID and actual context depth. Do not claim a full recursion path from a single snapshot; invocation/depth and chronological trace let frontend retain caller workspaces. BEFORE_LOCATION leaves current mark/call pending; actual observed visited flags are authoritative. Unknown/truncated data never fabricates vertices/edges/completion.

Reuse existing bounded field-only graph/visited projection by extending declaration selectors to DFS hints; preserve BfsProjection public compatibility and BFS behavior. Do not invoke target methods through JDI. No custom recursive object traversal or new dependencies.

OPERATIONS retains generic schemaVersion2 steps and same DFS hints. Recursive matrix example is supported end-to-end: main executes first, call BEFORE then nested steps and METHOD_EXIT then caller AFTER. Every ordinary statement/local lifetime remains. Library list construction may remain unsupported in strict operation mode; document explicit422 rather than silently fallback. Do not attach legacy dfsFrame to operation phases or synthesize recursion events not captured.
